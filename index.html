Open Data Guide

Turn a dataset URL into an understandable, inspectable question.

This guide helps people who are not data specialists explore public government datasets published on CKAN and DKAN open-data catalogs. You pick a dataset, understand its fields, ask a plain question, and read a clear answer — all in your own browser.

Data is queried in your browser. No account or application server is required. Saved markers may keep up to 100 preview rows for review, and saved analyses may keep bounded result previews.

What can and cannot be opened in the browser
  • Cross-origin (CORS): a catalog or file must allow browser requests from other sites. Many do not, so some datasets cannot be read here even though they open in a normal browser tab.
  • Authentication: datasets that need an API key, sign-in, or token are not supported; this guide only opens public resources.
  • Format: direct files must be CSV, JSON, or Parquet. Local uploads currently support CSV only.
  • Size: browser memory is limited. Automatic loading is refused above 500 MB, and large files may still be slow.

Not every open dataset is browser-accessible. Finding a dataset in a catalog does not guarantee its files can be opened here.

Search open data catalogs

Searches are sent directly from your browser to the catalog you select. There is no Open Data Guide server in between. Whether a search succeeds depends on the catalog allowing cross-origin browser requests. A dataset appearing here does not guarantee its files can be opened directly in the browser.

Processing and AI

          
Your data is processed in this browser. Open Data Guide has no application server, account, analytics, or telemetry. It does not send your source rows or questions to an Open Data Guide service.

          
    
            
  • Regular queries: deterministic JavaScript and DuckDB-Wasm run the calculations locally. This is code, not AI.
    • 
            
  • Optional AI planning: a browser-provided model or the approved Hugging Face model runs in this browser. AI only suggests a constrained plan; deterministic code validates and runs it.
    • 
            
  • Downloads: browser-provided AI may download a browser-managed model after you approve it. The optional Hugging Face planner downloads about 500 MB after approval. Optional semantic matching downloads a pinned MiniLM model of about 23 MB plus runtime files after approval.
    • 
            
  • Network requests: the browser may request catalog metadata, dictionaries, and selected data directly from the publisher or catalog you open. Remote DataStore requests include the selected fields, filters, and page limits needed for the query; the returned data and all calculations are processed in this browser. These are source requests, not requests to an Open Data Guide server.
    • 
            
  • Local execution limits: DuckDB-Wasm cannot currently be interrupted once synchronous parsing or a query has begun; the app keeps the query visible and avoids claiming a partial result is complete.
    • 
            
  • Optional semantic matching sees: dataset titles, descriptions, and field descriptions. It does not use raw dataset rows.
    • 
          

          
Use “Check browser AI support” below to see what your browser exposes. Checking does not download a model. AI is never required for the deterministic query workflow.
